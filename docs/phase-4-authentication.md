# Phase 4 — Authentication & Authorization

## النطاق

هذه المرحلة تضيف أساس المصادقة والصلاحيات للحسابين الثابتين في مواصفات AIS:

- `AIS`: صلاحية `ADMIN`.
- `User`: صلاحية `VIEWER`.

كلمات المرور لا تُخزّن كنص صريح ولا تُحفظ في الواجهة. تتم تهيئتها من متغيرات بيئة عند تشغيل سكربت bootstrap مخصص لاحقاً.

لتهيئة الحسابين محلياً، يضبط المشغّل `AIS_ADMIN_PASSWORD` و`AIS_VIEWER_PASSWORD` في بيئته ثم يشغّل `npm run auth:seed`. القيم الحقيقية لا تُضاف إلى `.env.example` ولا إلى المستودع.

## حدود الأمان

- كلمات المرور تُجزّأ باستخدام `crypto.scrypt` مع salt عشوائي ووقت ثابت للمقارنة.
- الجلسة تعتمد على رمز عشوائي؛ لا يُخزّن الرمز الخام في قاعدة البيانات، بل بصمته SHA-256 فقط.
- كوكي الجلسة HttpOnly وSameSite=Lax، وتستخدم Secure في الإنتاج.
- جلسات منتهية أو ملغاة لا تُقبل.
- الصلاحيات تُفحص في الخادم، ولا تُعتبر واجهة المستخدم حاجزاً أمنياً.
- لا يتم تسجيل كلمات المرور أو رموز الجلسات.

## نموذج البيانات

أضيف `AuthSession` إلى PostgreSQL عبر جدول `ais_auth_sessions` ويرتبط بـ `User` بعلاقة واحد إلى متعدد. حذف المستخدم يحذف جلساته، مع فهارس على المستخدم وحالة الجلسة وتاريخ الانتهاء.

## الصلاحيات

`ADMIN` يستطيع إدارة الجهات والحوالات والتسويات والإعدادات وسجل التدقيق، إضافة إلى العرض والطباعة والتصدير.

`VIEWER` يستطيع العرض والبحث وقراءة الكشوف والطباعة والتصدير فقط، ولا يستطيع الإنشاء أو التعديل أو الحذف أو التسوية أو تغيير الإعدادات.

## الاختبارات

تشمل اختبارات المرحلة تجزئة كلمات المرور والتحقق منها، رفض كلمات المرور الضعيفة، اختلاف الـ salts، وفحص جميع صلاحيات الدورين.
