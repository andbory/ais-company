# AIS COMPANY — PHASE 3 FINANCIAL ENGINE

## الهدف

إنشاء محرك مالي نقي وقابل للاختبار يحسب أثر الحوالات والتسويات على رصيد جهة واحدة وعملة واحدة، ثم يوسعه لاحقاً إلى كشف الحساب وطبقة الخادم.

## حدود الشريحة الحالية

- لا PostgreSQL.
- لا API.
- لا React state.
- لا مزامنة.
- لا تعديل أرصدة يدوياً.
- لا تحويل بين العملات.

## القواعد

- جميع المبالغ تدخل كسلاسل عشرية وتخزن داخل المحرك بوحدات صحيحة scaled integers.
- `total = amount + commission`.
- `SENT` يزيد `WE_ARE_OWED`.
- `RECEIVED` يزيد `THEY_ARE_OWED`.
- `THEY_PAID_US` يقلل `WE_ARE_OWED`، والزيادة تعكس إلى `THEY_ARE_OWED`.
- `WE_PAID_THEM` يقلل `THEY_ARE_OWED`، والزيادة تعكس إلى `WE_ARE_OWED`.
- العملة لا تتغير داخل العملية ولا تختلط بعملة أخرى.
- الصفر والقيم السالبة غير صالحة للعمليات المالية.

## عقد القبول

- كل الاختبارات المالية الأساسية تمر.
- USD لا يؤثر في IQD أو EUR أو SAR أو IRR_TOMAN.
- commission محفوظة منفصلة عن amount، وtotal لا يقبل قيمة محسوبة من العميل.
- التسويات الجزئية والكاملة والزائدة تعطي أثراً حتمياً.
- لا يستخدم المحرك JavaScript floating point للمبالغ.

## التنفيذ الحالي

- `src/domain/financial/financial-engine.ts`: محرك الحسابات النقي وإعادة تشغيل العمليات.
- `tests/financial-engine.test.ts`: عشرة اختبارات مالية باستخدام `node:test`.
- `package.json`: الأمر `npm run test:financial`.

## نتيجة الشريحة الأولى

تم اجتياز الاختبارات العشرة: حساب الإجمالي، الحوالة المرسلة، الحوالة المستلمة، التسوية الجزئية، التسوية الزائدة في الاتجاهين، عزل العملات، التحقق من القيم، العملات الخمس، وإعادة بناء الرصيد من الرصيد الافتتاحي والعمليات.
